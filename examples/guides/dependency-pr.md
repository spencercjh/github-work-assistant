# 依赖更新 PR 委托示例

此文件是配置模板，复制到安装目录并由仓库负责人确认后才生效。示例配合 `mode=local-edit`、`github_actions=["merge"]`，允许执行者自行判断并合入本仓库中 Dependabot 发起的依赖更新；是否修复、推送或评论需另列对应动作。重大版本、业务代码和发布流程变更不在本示例范围内。

## 处理目标

检查依赖更新的实际 diff、上游变化、锁文件一致性、当前提交的构建和安全检查，结合项目使用方式判断影响。不能仅凭标题、补丁版本号、机器人兼容性分数或绿色图标决定合入。检查详情若写明跳过审阅，不算已有审阅批准；执行者应自行审阅改动。

测试命令以配置为准。可信且针对当前提交的构建可作为证据；需要补充验证时，在隔离工作树中执行。检查失败、审阅提出未解决的问题或版本发生变化时，先调查并继续处理授权范围内的工作；需要超出范围的修改时，说明具体改动和影响。

## 合入和跟进

当改动符合委托范围、验证足够、没有未解决的阻塞意见且 GitHub 允许合并时，自行合入，无须再次请求相同授权。合入前运行 check-github-action，核对当前 head/base 和任务归属；使用 gh 的 --match-head-commit，并遵守仓库分支规则，不使用管理员绕过。

操作后查询实际状态，记录合并 SHA、验证证据和结果。等待检查时保存等待条件并继续跟进同一事项。无法判断的业务取舍和明确授权缺口才交给负责人；无需为每次检查成功或机器人回复发送提醒。
