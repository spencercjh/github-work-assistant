# 当前版本验证记录

日期：2026-10-21。环境：Linux amd64、Go 1.26.5、seekdb 1.4.0.0。

## 自动化验证

使用与运行服务分离的 seekdb 容器和数据库执行 `make integration`，启用 Go race 检查。数据库名为 `ghraft_test`；缺少数据库、使用非 loopback 连接或数据库名没有 `_test` 后缀时，必需的集成测试会失败。17 个测试通过，没有跳过数据库测试。

验证覆盖：

- 显式关注、公开通知发现、评论修改、首次观察的 PR 状态和历史通知导入；重复采集不重复产生事件。
- head/base SHA、可合并／冲突／未知三态；同一 head 的 base 变化会使旧工作失效。
- 真实 seekdb 事务与持久化，响应丢失后的稳定事件 ID 重试、加密凭据、身份与会话撤销。
- 仓库指引版本、路径和符号链接边界、未配置仓库只读、Project-HAMi 调查限制。
- Raft task 关联的重复请求、冲突请求、历史报告和指引留存；报告内容不能被覆盖。
- 移除显式关注、仓库转私有后的读取及写入限制；105 条已撤销事件不会挡住后面的有效事件。
- 真实 Git worktree 冲突、保留两侧意图后的项目测试、原分支保持不变，以及不存在远端写入接口。

GitHub 采集测试调用真实 `gh` 子进程边界，但 PATH 中放置拒绝非 fixture GET 请求的替身。Raft HTTP 身份和事件服务是协议 fixture。测试中的 Git 历史是合成对象，不使用 `git commit` 或远端仓库。

`make build`、`make check` 通过。后者包含 `go vet`、Go 格式检查和 diff 检查。

## 实际 Raft 任务与本机 CLI

另外使用可保留的离线场景，由验收 Agent 在实际 Raft 任务内执行工作。真实任务及报告标识保留在原始私有验收材料中。

| 项目 | 结果 |
| --- | --- |
| 任务关联 | 实际 Raft 任务关联成功，标识不进入源码 |
| 交付消息 | 实际 Raft 报告已记账，标识不进入源码 |
| 采集事件 | `66f876302d5584f0250797f9d0f17346a0f6b4bcd83e5989d61dae9139a331db` |
| head | `3c3cd1fdfdd6fad5a19b4b33a93b3405b2cbc686` |
| base | `23587a23caefdac17f1577c11d183a861bf4e56c` |
| 项目测试 | `python3 -m unittest discover -v`，2 项通过 |
| 结果记账 | 两次独立 CLI 上报成功，历史只保留 1 条报告，pending 为空 |

场景中，base 将偏移量由 1 改为 2，PR 增加输入倍增行为。同一位置产生真实合并冲突。验收 Agent 在生成的 worktree 中将行为合成为 `x * 2 + 2`，使偏移量与倍增两项测试通过，然后运行 `verify-worktree`。原 PR 分支和 base 分支没有改动，工作树保持未提交状态。

这条链路验证了「本机采集 → 仓库指引 → 真实 Raft 任务关联 → Agent 本地修改和测试 → 真实 Raft 报告 → 数据库记账」。GitHub 来源为离线 fixture，没有向真实 GitHub 发送评论、review、PR 或提交。

## 验证范围

本次候选代码没有替换原有通知服务。此前版本的 App 注册和事件接入属于历史验收，见 [VALIDATION.md](../VALIDATION.md)。本轮不能据此声称新的接收 Agent、真实 App 推送或离线 Agent 冷启动已经验收。

未验证长期零漏报、多用户服务、私有 GitHub 事项、跨机器 worktree 管理、真实机器重启、远端自动推送或合并。没有这些能力的默认授权。

报告中的测试结果由 Agent 上报，App 保存版本和关联，不独立证明外部测试确实执行。仓库指引与工具检查不构成项目代码执行沙箱；不可信代码需要独立的隔离执行环境。
